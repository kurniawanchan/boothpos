# WJM POS design screens digest (design/screens)

Source: /Users/chan/www/warkopwjm/design/screens. Language of UI copy: Indonesian. Design system: Material 3 (seed red #EC3013), Roboto Flex, Material Symbols/Lucide-style icons.

## Structural finding (fact)
All 37 NN-*.dc.html files are the SAME single-page app (same template, 88-90 KB each). They differ only in 4 globals set in a header script: `POS_PRESET` (initial state), `POS_THEME` (Terang/Gelap), `POS_DEVICE` (default Tablet 10" landscape 1180x740), `POS_CONN` (Online/Offline/Offline terbatas). 00 = full interactive prototype with no preset. So "per screen" = a preset of one app. Footer label on every mock: "PIN demo: 6 digit apa saja" (any 6 digits except 000000 pass). tablet/ holds 01..36 PNG captures + _contact-sheet.png (no other files). Other files: support.js, image-slot.js (photo slots for menu items), m-icon.js (icon helper). Design context: outlet "Warkop WJM 3", terminal T01, "Kab. Bogor", demo date Sabtu 31 Oktober 2026, Shift 1 07:00-15:00.

Device classes: compact <600dp, medium 600-839, expanded 840-1199, large >=1200. Devices: Tablet 10" landscape 1180x740; 13" landscape 1366x1000; 8" portrait 800x1180; phone portrait 390x844. Table grid columns: 3 compact / 4 medium / 6 expanded / 8 large. Menu grid 2/3/4/5. Compact uses bottom nav + bottom sheets; larger uses right side sheets (440px, 400px medium) and left category rail (160px, expanded+).

## App shell (all screens except login/open-shift)
Header: "WJM 3 · T01", user name + role, date, "Shift 1 sejak HH:MM" or "Belum ada shift"; connectivity chip (Online / "Menyinkronkan · N" / "Offline · N tersimpan" / "Offline terbatas"); print-failure chip "Cetak gagal · N"; lock button (returns to PIN). Nav tabs: Meja, Counter (creates a new counter order), Order (badge = open order count), Shift; plus a Sync/Perangkat entry. Banners: offline-limited = "Perangkat offline lebih dari 4 jam. Order baru perlu persetujuan Outlet Manager dan tunai baru ditolak. EDC tetap bisa dipakai."; photo-mode banner (design tool only).

## Business rules, presets, thresholds encoded in pos-app-logic.js
Money/tax: tax 10% (taxRate 0.10) EXCLUSIVE, computed on base after discounts; Math.round everywhere; total = base + tax. Order: gross = sum(unit*qty) of non-voided; line discount % per line; order discount % applied after line discounts. Paid = sum of tenders with status ok.
Discount limits by role (placeholder, "PRD §8.4 levels; values pending OQ-023"): CSH 10%, WTR 0%, SPV 50%, OMG 100%. Line/order discount above own limit -> override by SPV/OMG whose limit >= requested pct (the 20% preset needs SPV/OMG for a cashier; 10% preset is self-approvable by CSH).
Override (4-eyes) required: void line (always unless user is SPV/OMG; CSH/WTR show lock), cancel order, refund (SPV/OMG), availability/86 toggle (SPV/OMG; CSH/WTR told Supervisor needed), QRIS verification (SPV/OMG), cash-out > Rp 200.000 (cashOutThreshold, strictly greater), reprint beyond reprintFree = 1 copy, new order when offline-limited (OMG only), cash variance beyond tolerance. Approver cannot be the requester; shift-close variance cannot be approved by the cashier themself (roles filtered by r !== user.code).
Variance tolerance Rp 5.000 (abs, strictly greater needs approval; also red display). Blind count: system expected not shown until counted; expected = float + cash sales + cash-in - cash-out - cash refunds.
PIN: 6 digits, auto-submit; lockout 15 min after 5 wrong (only message in mock; counter pinFails); override PIN shows "Sisa 4 percobaan" (static). Demo: 000000 = wrong.
Offline: three states Online / Offline / Offline terbatas (>4 h offline). Offline: QRIS disabled, refund disabled, closing shift disabled (gate), orders on other devices (T02) not openable, PIN verified against stored data, events queue in outbox (cap 400 kept in UI) and auto-sync ~1.3 s after reconnect. Offline-limited: new orders need OMG approval, cash tender rejected, EDC allowed. Offline cash exposure cap Rp 3.000.000, warning at 50% (text in sync screen only). Heartbeat 60 s; sync batch max 50 events; device clock skew warning > 5 min; menu release version 17.
EDC: approval code ^[A-Z0-9]{6,12}$; card number never stored; duplicate window 120 s (same method + same amount on same order) -> confirm dialog. Only one EDC/QRIS method ("EDC BCA", "QRIS GoPay") hardcoded, TID 0091 shown at close.
QRIS: static QR, record as pending, verify later with reference (>=4 chars); pending blocks other non-cash tender and blocks shift close; failed marks 'fail'.
Cash tender: amount recorded = min(received, target); change = received - amount; split by N: part = min(remaining, ceil(total/N)) (N 2-5); quick-cash = exact, next 10k, 50k, 100k multiples (unique, max 4); keypad max 9 digits.
Order rules: counter queue numbers A-NNN (seed 24, 3-digit), receipt numbers T01-000124 (6 digits, terminal prefix, sequential); order close when remaining = 0; counter order fires unfired lines automatically on close (KOT) and prints receipt; dine-in pax 1-8; line merge rule (same item, same mods, unfired, no note/discount); note max 100 chars; fired lines cannot be reduced, only voided; cancel blocked with any ok payment; split-by-item blocked with payments and requires at least 1 moved and at least 1 kept item; waiter cannot pay (primary action = pre-bill with "BELUM LUNAS"); open shift required to take payment; shift open with Rp 0 asks confirm; shift schedule 07:00-15:00 (suggested from outlet schedule).
Printing: auto retry 3x then fails to queue with Retry/Cancel; print kinds kot, receipt, prebill, void (Slip BATAL), reprint (SALINAN n), refund, report (X/Z). Printers: Kasir LAN 80 mm, Dapur LAN 80 mm.
Refund: full only, to original method; EDC/QRIS refunded manually on EDC machine or merchant portal; only closed orders; online only; cash refund reduces expected cash.
Outbox event types seen: order.opened, order.line.added/removed/voided/discount, order.fired, order.closed, order.cancelled, order.prebill.printed, order.discount, order.split, order.refunded, payment.recorded, payment.verified, payment.cancelled, shift.opened, shift.closed, cash.recorded, availability.set, receipt.reprinted, print.reported.
Not backed by real data in the mock (fabricated): hourly sales bars (hard-coded 07-11 values), "Versi 17", clock skew "4 dtk", table ages, seed orders.
