BoothPOS mengatur akses dalam dua lapis. Keduanya ditegakkan oleh server. Aplikasi web hanya menyembunyikan apa yang tidak dapat Anda pakai.

## Peran bawaan

Setiap instalasi dimulai dengan empat peran. Owner dan admin dapat mengubah peran, dan membuat peran khusus, di [Peran](/settings/roles).

| Peran | Akses menu saat instalasi | Izin aksi | Cakupan outlet |
| --- | --- | --- | --- |
| Owner | Semua menu | Semua izin aksi | Semua outlet |
| Admin | Semua menu | Semua izin aksi | Semua outlet |
| Kasir | Beranda, Kasir, Sesi Kasir, Pelanggan, Penjualan, Lantai & Tab, Dapur & Bar | Tidak ada secara bawaan | Hanya outlet yang ditugaskan |
| Inventory | Beranda, Kasir, Sesi Kasir, Produk, Outlet, Kategori, Stok, Vendor, Bahan Baku, Pelanggan, Penjualan, Pengaturan Restoran | Mengelola item, menandai item 86, mengubah resep, mengirim dan menerima transfer stok, menandai habis (sold out) | Hanya outlet yang ditugaskan |

<Note>
  ASUMSI: daftar menu di atas adalah bawaan yang dibuat oleh migrasi instalasi. Peran dapat diubah setelahnya, sehingga peran yang ada di hadapan Anda mungkin berbeda. Layar Peran adalah sumber kebenaran untuk sebuah toko.
</Note>

Owner dan admin dikenali dari nama peran (tanpa membedakan huruf besar-kecil) untuk izin aksi bawaan. Peran yang Anda buat sendiri hanya mendapat izin yang Anda centang.

## Kunci menu

Kunci menu membuka sebuah layar. Beberapa item navigasi dapat berbagi satu kunci.

| Kunci menu | Membuka |
| --- | --- |
| `dashboard` | Beranda (Dashboard) |
| `pos` | Kasir (POS) |
| `session` | Sesi Kasir |
| `sales` | Penjualan |
| `floor` | Lantai & Tab |
| `kitchen` | Dapur & Bar |
| `dining_setup` | Pengaturan Restoran |
| `categories` | Kategori |
| `products` | Produk dan detail produk |
| `stock` | Stok dan transfer stok |
| `vendors` | Vendor |
| `materials` | Bahan Baku |
| `purchase_orders` | Purchase Order |
| `customers` | Pelanggan |
| `outlets` | Outlet |
| `reports` | Laporan dan Log Aktivitas |
| `settings` | Pengaturan General dan Pembayaran |
| `users` | Pengguna |
| `roles` | Peran |
| `companies`, `licenses`, `invoices` | Grup Admin sisi penyedia (tidak dibahas di sini) |

<Warning>
  Kunci `users` dan `roles` dilindungi. Toko harus selalu memiliki setidaknya satu peran yang mencakup keduanya, sehingga tidak ada instalasi yang dapat mengunci dirinya sendiri dari pengelolaan pengguna dan peran.
</Warning>

## Izin aksi

Izin ini diperiksa selain akses menu.

| Izin | Yang diizinkan |
| --- | --- |
| Mengelola item (diskontinu, aktifkan kembali) | Mendiskontinu dan mengaktifkan kembali item. |
| Menandai item habis (86) | Menandai item tidak tersedia. |
| Menandai item habis (sold out) tanpa persetujuan | Menandai item habis tanpa perlu disetujui orang lain. |
| Mengubah harga massal | Mengubah harga secara massal. |
| Menyetujui perubahan harga | Menyetujui perubahan harga yang tertunda. |
| Menerbitkan rilis menu | Menerbitkan rilis menu. |
| Mengubah resep | Mengubah resep item (bill of materials). |
| Mengirim transfer stok antar outlet | Mengirim stok ke outlet lain. |
| Menerima transfer stok antar outlet | Menerima stok yang dikirim dari outlet lain. |
| Membatalkan transfer stok yang belum diterima | Membatalkan transfer yang belum diterima. |
| Membatalkan (void) baris yang sudah dikirim ke dapur | Mem-void baris yang sudah dikirim ke dapur. |
| Membatalkan seluruh tab terbuka | Membatalkan satu tab terbuka secara utuh. |
| Menyetujui kas keluar di atas batas | Menyetujui kas keluar yang lebih besar dari batas. |
| Menyetujui cetak ulang struk | Menyetujui cetak ulang struk. |
| Memverifikasi atau menandai tidak ditemukan pembayaran QRIS | Memverifikasi, atau menandai tidak ditemukan, sebuah pembayaran QRIS. |
| Refund penuh order lunas | Me-refund penuh order yang sudah dibayar. |
| Menyetujui selisih kas tutup shift di atas toleransi | Menyetujui selisih kas saat penutupan yang melebihi toleransi. |
| Menyetujui diskon di atas batas peran | Menyetujui diskon yang melebihi batas diskon peran itu sendiri. |

### Persetujuan di titik aksi

Beberapa aksi, seperti void, diskon besar, atau cetak ulang, memerlukan seseorang dengan izin yang sesuai. Jika Anda memegang izin itu, aksi langsung berjalan. Jika tidak, server meminta konfirmasi dari seorang penyetuju menggunakan PIN persetujuan. PIN penyetuju tidak pernah ditampilkan di mana pun. Lihat [Pengguna](/settings/users) untuk cara PIN diatur.

<Warning>
  Aplikasi web tidak memiliki prompt PIN persetujuan. Alur persetujuan dibuat untuk Android POS. Di web, aksi yang memerlukan persetujuan yang tidak Anda miliki dapat gagal alih-alih meminta persetujuan, misalnya saat membatalkan item yang sudah dikirim ke dapur. Halaman setiap modul menyebutkan di mana hal ini berlaku.
</Warning>

## Cakupan outlet

Peran dapat ditandai agar **melihat semua outlet** (owner dan admin). Setiap pengguna lain hanya melihat outlet yang ditugaskan kepadanya. Lihat [Outlet](/concepts/outlets).

## Saat akses ditolak

| Yang Anda lihat | Artinya |
| --- | --- |
| Sebuah layar tidak ada di rail | Peran Anda tidak memiliki akses menu ke layar itu. Tanyakan kepada owner atau admin. |
| Diarahkan ke Dashboard setelah mengetik alamat | Penyebabnya sama. |
| Galat izin (HTTP 403) saat Anda mengklik sebuah aksi | Layar terbuka untuk Anda, tetapi aksi itu memerlukan izin yang tidak Anda miliki. |
| Prompt persetujuan | Aksi itu memerlukan penyetuju. |
