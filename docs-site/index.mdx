**Classification: INTERNAL**

BoothPOS is a point-of-sale system installed locally for each store. The web app is the screen your team uses at the counter and in the back office. It runs in a browser on the same machine or shared server as the BoothPOS API, so it keeps working at an event venue with poor internet.

This guide covers every module of the web app that your store uses day to day. It is written for shopkeepers, cashiers, inventory staff, owners, and admins.

<Info>
  What you see depends on your role. Modules your role cannot use are hidden, not greyed out. See [Roles and permissions](/concepts/roles-and-permissions).
</Info>

## Key ideas

<AccordionGroup>
  <Accordion title="Outlets">
    One organisation can run one or more outlets. Each sale, shift, table, and stock balance belongs to one outlet. See [Outlets](/concepts/outlets).
  </Accordion>
  <Accordion title="DEMO and LIVE">
    Two separate data sets share one installation. The top bar badge always shows the active one. See [DEMO and LIVE mode](/concepts/demo-and-live-mode).
  </Accordion>
  <Accordion title="Business day">
    Reports group by business date, set by your store time zone and cut-off. See [Business day](/concepts/business-day).
  </Accordion>
</AccordionGroup>

## What this guide does not cover

- Provider-side administration (Companies, Business Types, Licenses, Invoices).
- Events and pre-orders. These modules were removed and old addresses redirect to the Dashboard.
- Developer topics such as installation, Docker, and the API. See the repository `docs/RUNBOOK.md` and `docs/openapi-pos-mvp.yaml`.
