The **Users** screen lists the accounts that can sign in to BoothPOS. From it you create accounts, change roles, switch accounts on or off, assign outlets, upload photos, and set the PIN staff use on the tablet.

## Before you start

- You need the **Users** menu (menu key `users`) to open the screen and to create, edit or delete users.
- **Set PIN / Reset PIN** needs the **Settings** menu (`settings`), not just **Users**. The button is hidden without it, and the server answers 403 if it is called anyway.
- Only accounts of the **current data mode** are listed: DEMO and LIVE have separate user lists. See [DEMO and LIVE mode](/concepts/demo-and-live-mode).
- A role must exist before you can give it to a user. See [Roles](/settings/roles).

## The user list

| Column | Meaning |
| --- | --- |
| **Name** | Name, with photo or initial. |
| **Username** | The sign-in name. |
| **Role** | The user's role. |
| **Outlets** | Only shown when the organisation has more than one outlet. **All outlets** for roles that see everything, **Not assigned** (in red) if none, otherwise the outlet codes. |
| **PIN** | **Has PIN**, **No PIN**, or **Locked** (too many wrong PIN attempts). |
| **Last Access** | Last sign-in time, or **Never**. |
| **Status** | **Active** or **Inactive**. |

Users are sorted by name, 25 per page.

### Search and filters

| Control | Effect |
| --- | --- |
| Search box (**Search name or username…**) | Matches part of the name or the username. |
| **All roles** | Filter by one role. |
| **All statuses** | **Active** or **Inactive**. |
| **All PIN statuses** | **Has PIN** or **No PIN**. |

The reset control clears all of them. The counter shows the total of the filtered result.

## Create a user

<Steps>
  <Step title="Add user">
    Click **Add user**. The **New user** dialog opens.
  </Step>
  <Step title="Fill the form">
    Enter **Name**, **Username**, **Password**, and choose a **Role**. Optionally pick a **Photo** (JPEG or PNG). **Active** is ticked by default.
  </Step>
  <Step title="Assign outlets (more than one outlet only)">
    If the organisation has more than one outlet and the chosen role does not see all outlets, a list of outlet checkboxes appears. Tick the outlets this user works in.
  </Step>
  <Step title="Save">
    Click **Save**. You see **User created.**
  </Step>
</Steps>

### Field rules

| Field | Rule |
| --- | --- |
| **Name** | Required, up to 100 characters. |
| **Username** | Required, up to 50 characters, unique among existing users (deleted users do not count). Sign-in uses the username, not an email. |
| **Password** | Required when creating, at least 8 characters. When editing, leave blank to keep the current password. |
| **Role** | Required, must be an existing role. |
| **Photo** | JPEG or PNG, up to 5 MB. |

Saving is done in separate steps: the account first, then the photo, then the outlets. If the photo or the outlet assignment fails, the account is already saved and you get a separate error toast instead of the dialog staying stuck. Check the row afterwards.

<Note>
  On a single-outlet installation, a new user whose role does not see all outlets is assigned automatically to the only active outlet, so they can open a shift. With several outlets you must assign outlets yourself, or the user sees **This account is not assigned to any outlet. Ask an administrator to assign it.**
</Note>

## Edit a user

Click **Edit** on a row. The same form opens with the current values. You can change the name, username, role, password, photo, active status and outlets. Saved message: **User updated.**

## Assign outlets

The outlet list appears in the form only when there is more than one outlet and the selected role is not marked **Sees all outlets**. Owner and Admin always see every outlet and are never assigned (the server answers 409: **Owners and admins always see every outlet, so they are not assigned to particular outlets.**).

Rules enforced by the server on outlet assignment:

- You cannot change your own outlet assignment (403, **This outlet is not one you are allowed to access.**). Widening your own outlets would be a privilege escalation.
- If your own role does not see all outlets, you can only add or remove outlets you can see yourself (403 otherwise).
- Only active outlets of the current mode can be assigned (**The outlet was not found or is inactive.**).
- Every assignment change is recorded in the [Activity log](/insight/activity-log) as `user_outlets_updated`.

See [Outlets](/concepts/outlets) for how outlet scope affects what a user sees.

## Set or reset a PIN

Staff sign in on the tablet with a 6-digit PIN. Owner and admin set it here; the PIN is never shown in the user list.

<Steps>
  <Step title="Open the PIN dialog">
    Click **Set PIN** on a user without a PIN, or **Reset PIN** on one who has a PIN. The title reads **Set PIN — \{name\}** or **Reset PIN — \{name\}**.
  </Step>
  <Step title="Type a PIN or generate one">
    Type exactly 6 digits in **PIN (6 digits)**, or click **Generate random PIN**. Use **Show PIN** / **Hide PIN** to reveal or hide what is in the field.
  </Step>
  <Step title="Save">
    Click **Save PIN**. You see **PIN for \{name\} saved.**
  </Step>
  <Step title="Pass the PIN on">
    For a generated PIN, note it now: the dialog says **Note the PIN below now. Once the dialog is closed it can't be shown again.** A PIN you typed yourself is not shown again at all.
  </Step>
</Steps>

What to know:

- The PIN must be exactly 6 digits and not too easy to guess. All-same digits (for example six identical digits) and straight runs up or down are refused with **PIN is too easy to guess (repeated or sequential digits).** Generated PINs always pass this rule.
- The generated PIN is requested from the server and only stored when you click **Save PIN**. Nothing is kept in the browser after the dialog closes.
- When you reset an existing PIN, the old PIN stops working, any lock is cleared, and the user must sign in again on the tablet.
- Five wrong PIN attempts lock the user's PIN for 5 minutes; the list then shows **Locked**. Resetting the PIN clears the lock.
- Each set or reset is written to the [Activity log](/insight/activity-log) as `pin_set` or `pin_replaced`. The log never contains the PIN.

<Warning>
  Treat a PIN like a password. Do not write it in chat, a ticket or a shared document.
</Warning>

Tablet terminals are registered from the tablet itself; this web screen has no terminal list. Open shifts show the terminal name in [Shifts](/operations/shifts).

## Deactivate or delete a user

Untick **Active** in the edit form to stop an account from being used without deleting it. To remove it, click **Delete** and confirm **Delete \{name\}?** You see **User deleted.** Deleting is a soft delete: the username becomes available again, and the action is written to the activity log.

### Protections on your own account

You cannot lock yourself out. These answer 409:

| Action | Message |
| --- | --- |
| Deactivate your own account, or change your own role | **You cannot deactivate or change the role of the account you are currently using.** |
| Delete your own account | **You cannot delete the account you are currently using.** |

The screen already hides **Delete** on your own row and disables **Role** and **Active** in your own edit form. The server enforces it even if the screen is bypassed.

## Troubleshooting

| Message or symptom | Cause | Fix |
| --- | --- | --- |
| Field error under **Username** | Already used (422). | Choose another username. |
| Field error under **Password** | Fewer than 8 characters. | Use a longer password. |
| **Set PIN** button is missing | You have **Users** but not **Settings**. | Ask an owner or admin, or give the role the **Settings** menu in [Roles](/settings/roles). |
| **PIN is too easy to guess (repeated or sequential digits).** | Weak PIN (422). | Pick another or use **Generate random PIN**. |
| **Could not save the PIN.** / **Could not generate a PIN.** | Request failed. | Try again. |
| **Not assigned** in the Outlets column | No outlet assigned. | Edit the user and tick at least one outlet. |
| User cannot open a shift: **This account is not assigned to any outlet.** | Same as above. | Assign an outlet. |
| **Failed to upload the user's photo.** | Wrong type or too large. | Use JPEG or PNG under 5 MB. |
| The role list is empty in the form | The roles list failed to load, or your role cannot read roles. | The roles list is read through the **Roles** menu on the server, so a user who has **Users** but not **Roles** gets an empty role drop-down (the screen swallows the 403). Give them both menus, or reload if it was a temporary failure. |
