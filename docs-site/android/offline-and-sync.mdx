The Android app is **online-first**. It does not keep a local queue of orders or payments to send later. Each action goes to the server when you press it, and the server is the record. This page explains what you see when the connection drops and how to check it.

## Before you start

- Everyone signed in can open the **Perangkat** screen and see the connection state. No special permission is needed.
- Wi-Fi problems are the usual cause. The server may also be switched off or on another network.

## Connection states

The chip in the header shows the state the app last learned.

| Chip | Meaning |
| --- | --- |
| **Memeriksa koneksi…** | Nothing has been checked yet since the app started. |
| **Online** | The last request reached the server. |
| **Offline** | The last request failed on the network (no answer, timeout). |
| **Offline terbatas** | Reserved for a tablet offline for a long time. See below. |

Only a network failure turns the chip to **Offline**. A refusal such as 401, 403, 409 or 422 still proves the server answered, so the chip stays **Online** and the message is shown instead.

<Warning>
  The chip is also tappable and cycles through the states by hand. It is a leftover from the design prototype. The next request from the app sets it back to what it really found. Tell staff not to rely on a tap.
</Warning>

### Offline terbatas and the banner

When the state is **Offline terbatas** a yellow banner appears under the header: "Perangkat offline lebih dari 4 jam. Order baru perlu persetujuan Outlet Manager dan tunai baru ditolak. EDC tetap bisa dipakai."

<Note>
  ASSUMPTION: this is a designed policy, not an enforced one. The code never moves the app to **Offline terbatas** by itself, and no rule in the app or the server blocks cash or requires approval after 4 hours offline. Only the manual chip tap shows the banner. Do not tell staff that cash is blocked offline.
</Note>

## What happens to actions while offline

Nothing is stored for later. Many actions (for example discount, refund, close shift) try up to three times on a network failure, with a short pause, then stop. Others fail on the first try.

| Action | While the server is unreachable |
| --- | --- |
| Sign in with a PIN | Fails with a network message. You cannot sign in. |
| Open the menu, floor, orders | Shows what was last loaded, or an error card with **Coba lagi** if nothing is loaded. |
| Send items, take payment, discount, void | Fails with the network message in a toast. Nothing is recorded. Press again once online. |
| Close shift | Toast: "Koneksi terputus. Kirim hitungan lagi; server tidak akan menutup dua kali." Send the count again. The server will not close twice. |
| Approvals | The approver list cannot load and the PIN cannot be checked. See [Approvals](/android/approvals). |
| Printing | The tablet talks to the printer directly. ASSUMPTION: a print of an already-loaded document works offline, but the order or payment behind it still needs the server. See [Printing](/android/printing). |

Actions that take money or change an order carry a one-time key. A retry after a dropped reply therefore uses the same key, and the server answers with the saved result instead of recording it twice.

<Tip>
  If you are unsure whether a payment or close went through, open **Order** or **Shift** and pull down to reload before you try again.
</Tip>

## The Perangkat screen

Open **Perangkat** (**Perangkat & sinkron**) from the rail. **Periksa koneksi** (check connection) sends a heartbeat now instead of waiting for the next one.

| Tile | Shows | Notes |
| --- | --- | --- |
| **Koneksi** | **Belum terhubung**, **Terhubung** or **Terputus** | Plus "Heartbeat terakhir OK \{HH:mm:ss\}". **Terputus** adds "server tidak terjangkau". |
| **Jam perangkat** (device clock) | Seconds of difference from the server | "Dalam batas ±5 dtk", or "Selisih lebih dari 5 dtk — koreksi jam perangkat". |
| **Rilis menu** | The menu release the server reports | **Belum ada rilis** if none. |
| **Siap EOD (perangkat ini)** | **Siap** with no open shift, otherwise **Belum** | End of day is run by the outlet manager in the back office. |

Below the tiles is the printer panel. See [Printing](/android/printing).

## Heartbeat

While the app is in front and someone is signed in, it sends a heartbeat to the server every 60 seconds. One is also sent right after sign-in. The heartbeat reports the app version and returns the server time, so the clock difference can be shown. It also refreshes the terminal name, so a rename by an admin on the web appears on the tablet. It stops when the app goes to the background. On the PIN screen there is no session, so the app instead reloads the staff list every 10 seconds to keep the chip honest.

A heartbeat that fails keeps the last good values and only flips the state to **Terputus** and the chip to **Offline** (network failures only). If the server answers that the terminal was revoked, see [Set up a terminal](/android/setup).

## Pull to refresh

Pull any of these screens down to reload: **Meja**, **Order**, **Shift**, the X report and close screens, and **Perangkat** (which rechecks the printer). The floor plan also reloads itself every few seconds. A failed refresh keeps the data already on screen.

## Troubleshooting

| Message | Cause | Fix |
| --- | --- | --- |
| Chip **Offline** | Network failure on the last request. | Check Wi-Fi, then press **Periksa koneksi**. |
| **Belum terhubung** | No heartbeat has succeeded since sign-in. | Press **Periksa koneksi**; check the server. |
| "Selisih lebih dari 5 dtk — koreksi jam perangkat" | Tablet clock differs from the server. | Turn on automatic date and time in Android settings. |
| "Sesi berakhir. Masuk kembali." | The PIN session is no longer valid. | Sign in again. See [Sign in with a PIN](/android/pin-sign-in). |
| "Koneksi terputus. Kirim hitungan lagi…" | Network dropped while closing the shift. | Send the count again. |
