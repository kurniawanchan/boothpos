**Counter** is the order screen for walk-up customers. You tap products into an order, adjust the lines, optionally send the items to the kitchen, and then pay. The same editor is used for table orders, see [Tables and dine-in orders](/android/tables). Prices, totals, discounts and tax on the screen always come from the server.

## Before you start

- Sign in with your PIN, see [Sign in with a PIN](/android/pin-sign-in).
- Open a shift first. Without one, **Order baru** gives "Buka shift dulu sebelum membuka order." See [Shifts on the tablet](/android/shifts).
- You need a connection. Every change to the order is saved on the server at once; there is no offline order queue, see [Offline and sync](/android/offline-and-sync).
- The menu is the one your outlet sells. Products carried only by another outlet do not appear, see [Outlets](/concepts/outlets).

## Start a counter order

On wide screens the left rail has a round **Order baru** (new order) button and a **Counter** item. On a phone-size screen the bottom bar has **Counter**.

- **Order baru** always opens a new order. The title reads **Counter** plus the queue number the server assigned, and the subtitle reads "Counter · panggil dengan nomor antrean" with your name.
- **Counter** in the rail returns to the counter order you are working on, or opens a new one if the active order is not a counter order.
- **Counter** in the bottom bar (phone size) opens a new order each time you tap it.
- If the terminal was revoked you see "Terminal ini dicabut. Tidak bisa membuka order baru."

<Warning>
An empty order stays open on the server. An open order blocks closing the shift. Do not tap **Counter** or **Order baru** without needing an order. See "Empty orders" below for how to clear one.
</Warning>

## The layout

| Screen size | Layout |
| --- | --- |
| Wide (landscape tablet) | Products on the left (60 percent), the order on the right (40 percent). |
| Medium | Products on top, the order panel below. |
| Phone size | Products only, with a bar at the bottom: "3 item · Lihat order" and the total. Tap it to open the order; the back arrow (**Kembali**) returns to the products. |

Pull down on the product area to refresh the menu. This also clears the cached photos, so a photo changed in the back office is fetched again.

## Find products

<Steps>
  <Step title="Pick a category">
    The strip at the top lists every category from the server. Swipe sideways to reach more. If the list is empty it reads "Belum ada kategori". Your choice is kept when the menu reloads; if the category disappears the first one is selected.
  </Step>
  <Step title="Or search">
    Type in **Cari menu** (search menu). Searching ignores the category and lists matching items. Clearing the text, or picking a category, returns to the grid.
  </Step>
</Steps>

If a category has no products you see "Belum ada menu di kategori ini." A search with no match reads **Tidak ada menu "teh"** with your text. While the menu loads you see a spinner; if loading fails you see the error with a retry button.

### What a product card shows

Without a search, the grid has one card per product.

| Part | Meaning |
| --- | --- |
| Photo | The image saved for the product or variant. With no photo (or if it fails to load) a tile with the initials is shown. |
| Round number at the top right | How many of this product are already in the order (all variants added up). |
| Pill at the bottom left | One pill at most. **Habis** (sold out) takes priority over a variant count such as **2 varian**, which takes priority over **Pilihan** (options). |
| Name and category | Product name and its category. |
| Price | One price, or a range such as "Rp 7.000–Rp 8.000" when variants differ. |
| **Stok 12** | The tracked stock, added up over variants. Not shown for items without tracked stock. |

Search results work per variant. The name reads "Produk — Varian" and each result is added directly, as on the web POS.

## Add an item

- **Product with one variant and no options:** tap the card. The line is added.
- **Product with one variant and options:** tap the card. The options sheet opens, see below.
- **Product with several variants:** tap the card. The variant list opens, titled with the product name and category, with "Pilih varian untuk ditambahkan ke order". Each row shows the photo, variant name, code, stock, price and **Pilihan** if it has options. Tap a row to add that variant; the list closes. If the variant has options the options sheet opens next.

If every variant of a product is sold out, tapping the card gives "Kopi Susu sedang habis." and nothing opens. Inside the variant list a sold-out row shows **Habis** and does nothing when tapped.

### Options sheet

The sheet is titled with the item name and price. Each option group shows its rule: **Pilih 1** (choose 1), **Hingga 2** (up to 2) or **Pilih 1–2**, with a badge **Wajib** (required), **Terpilih** (chosen) or **Opsional**. Options with a surcharge show "+4.000".

- Single-choice groups behave like radio buttons; multi-choice groups stop at the maximum.
- Add a **Catatan untuk dapur** (note for the kitchen) of up to 100 characters.
- Use the stepper for the quantity, then tap **Tambah** (add), which shows the line total.
- If a required group is empty, **Tambah** does not add the item. The group is outlined in red and the sheet says "Pilih level gula dulu."

The server merges identical lines that were not yet sent, so tapping the same product twice raises the quantity of one line.

## Mark an item sold out (86)

Press and hold a single-variant product card, a search result, or a row in the variant list. Multi-variant cards do not react to a long press; open the list and hold the variant you want.

<Steps>
  <Step title="Choose a reason">
    The dialog **Tandai Es Teh habis?** asks you to pick an **alasan** from the server list. The item cannot be ordered until it is available again.
  </Step>
  <Step title="Tap Tandai habis">
    A message reads "Es Teh ditandai habis." Every tablet sees it within about five seconds.
  </Step>
</Steps>

- If the server has no active reason in the sold-out category, the dialog says so and the item cannot be marked from the tablet.
- Holders of the menu availability permission mark items without approval. Everyone else gets the **Perlu persetujuan** sheet and an approver's PIN, see [Approvals](/android/approvals). Owners, admins and the inventory role hold it by default.
- Sold-out cards are dimmed and hatched with the **Habis** pill. There is no button on the tablet to make the item available again. ASSUMPTION: this is done in the back office, see [Products](/inventory/products).
- The sold-out state is the server's list; the **Stok** number is for display only and does not block an order.

## The order panel

Lines are grouped under **Belum dikirim** (not yet sent, red) and **Sudah dikirim ke dapur** (already sent to the kitchen). A new order shows "Ketuk menu untuk menambah item".

| On a line | Meaning |
| --- | --- |
| Plus and minus stepper | Only on lines not yet sent. Minus at 1 removes the line. The quantity stops at 999. |
| **2×** pill and "Terkirim 14:05" | A sent line. It has no stepper. |
| Options, note | Chosen options and the note in quotes. |
| Discount pill | The percentage when a line discount applies. |
| Number at the right | The line total from the server. |

### Line actions

Tap a line to open its sheet.

- **Not sent yet:** stepper for **Jumlah**, a **Catatan** field (100 characters), **Diskon item…**, **Hapus** (delete) and **Simpan** (save). Changing nothing and tapping **Simpan** just closes the sheet.
- **Already sent:** the sheet says "sudah dikirim ke dapur" and "Perubahan jumlah dilakukan lewat void." The only action is **Void item**, see [Tables and dine-in orders](/android/tables).

### Order actions

The three-dot button on the panel opens **Aksi order**: **Cetak pre-bill**, **Cetak ulang KOT** (only when something was sent), **Diskon order**, **Bagi bill** and **Batalkan order**. Splitting and cancelling are described in [Tables and dine-in orders](/android/tables).

## Discounts

Open **Diskon order** from the order actions, or **Diskon item…** from a line. Use the stepper to set **Potongan** (1 to 100 percent, starting at 10), pick an **Alasan** (reason) from the server list and tap **Terapkan diskon**. Messages: "Diskon order diterapkan." or "Diskon item diterapkan." **Hapus diskon order** appears when an order discount exists.

- Each role has a discount limit on the server. Owners and admins default to 100 percent; other roles default to 0, so every discount from a cashier needs an approver unless an administrator set a limit. Above your limit the **Perlu persetujuan** sheet opens. A person cannot approve their own discount. See [Approvals](/android/approvals).
- If the server has no active discount reason, the sheet says "Server belum punya alasan diskon aktif" and you cannot apply a discount.

## Totals, sending and paying

When totals are visible the panel shows **Subtotal**, **Diskon** (red, negative; "Rp 0" when none), the tax line named by the server with its rate, **Total** and **Terbayar** (paid) once something was paid. **Sembunyikan total** (hide totals) collapses this to a single "Total Rp 45.000" line with **Tampilkan total**; the tablet remembers your choice.

- **Kirim N** sends the N unsent items to the kitchen. It is disabled with nothing to send. The message is "3 item dikirim ke dapur · KOT dikirim ke printer", or "... KOT belum tercetak, printer belum tersambung" when no printer is connected. A red notice "KOT belum tercetak — kirim ulang ke dapur secara manual" stays on the panel while the kitchen ticket is waiting or failed. See [Printing](/android/printing).
- **Bayar** goes to the payment screen. It is disabled while the order is empty. For a waiter the button reads **Cetak pre-bill** instead. See [Payment](/android/payment).
- Sending is optional for a counter order: you can pay without sending.

### Empty orders

An order with no items can only be removed with **Batalkan order**, which needs the order-cancel permission or an approver. There is no separate "close empty order" button on the tablet.

<Note>
ASSUMPTION: The server allows closing an empty tab, but the tablet code has no control that calls it. Ask an administrator to cancel stray empty orders if a shift will not close.
</Note>

## Troubleshooting

| Message | Cause | Fix |
| --- | --- | --- |
| "Buka shift dulu sebelum membuka order." | No open shift. | Open one, see [Shifts on the tablet](/android/shifts). |
| "Kopi Susu sedang habis." | The item or all variants are sold out. | Choose another item. |
| "Pilih level gula dulu." | A required option group is empty. | Choose an option, then **Tambah**. |
| "Item sudah dikirim ke dapur — batalkan lewat void." | You tried to delete a sent line. | Use **Void item**. |
| "Mengurangi jumlah dilakukan lewat void." | Minus on a sent line. | Use **Void item**. |
| "Item ini sudah dikirim ke dapur dan tidak bisa diubah di sini." | The line was sent from another tablet meanwhile. | Reopen the order and use void. |
| "Tidak ada item baru untuk dikirim ke dapur." | Everything was already sent. | None needed. |
| Spinner, then an error with a retry button | The menu could not be loaded. | Tap the retry button or pull down. |
