Some actions need a second person to agree. When you do one of them without the right permission, the app opens the **Perlu persetujuan** (approval needed) dialog. An approver chooses their name, enters their own PIN, and the action is repeated with a one-time approval. You, the requester, do not need to know the approver's PIN.

## Before you start

- You are signed in and have started the action (for example **Void** on a line).
- An approver who holds the matching permission is available, is not you, has a PIN and is assigned to this outlet.
- The tablet is online. Approvals are checked by the server and cannot be done offline. See [Offline and sync](/android/offline-and-sync).

## Ask for an approval

<Steps>
  <Step title="Do the action">
    Fill in the action as usual, with its reason, and confirm it. If your role may not do it alone, the server answers that approval is needed, and the dialog opens by itself.
  </Step>
  <Step title="Read the summary">
    The dialog repeats what is being approved, for example "Void 1× Kopi Susu · Salah pesan. Diminta oleh \{your name\}."
  </Step>
  <Step title="Pass the tablet to the approver">
    The approver list shows each eligible person with initials, name and role. The first person is selected. The approver taps their own name.
  </Step>
  <Step title="Approver enters the PIN">
    Six dots show the digits typed. The approver presses **Setujui** (approve) once all six are in.
  </Step>
  <Step title="The action runs again">
    The dialog closes and the app repeats the action with the approval. A toast confirms the result as for any normal action.
  </Step>
</Steps>

## Controls

| Control | What it does |
| --- | --- |
| Approver chips | Choose who approves. Changing the choice clears the PIN and the error. |
| Keypad | Six digits. Locked while the check runs. |
| **Setujui** | Enabled only with an approver chosen and all six digits entered. |
| **Batal** (cancel) | Closes the dialog. The action is not done. |

The dialog notes: "Persetujuan berlaku untuk satu aksi ini saja dan dicatat." The approval is for this one action only and is recorded in the activity log.

## Which actions need approval

| Action on the tablet | Approval is needed when |
| --- | --- |
| Void a line already sent to the kitchen | You lack the void permission. |
| Cancel a whole open tab | You lack the cancel permission. |
| Cash out of the drawer | The amount is above the cash-out limit set on the server and you lack the cash-out approval permission. Cash in never needs approval. |
| Close shift | The cash difference is above the tolerance set on the server and you lack the variance permission. |
| Mark an item sold out (86) | You lack the sold-out permission. |
| Verify a QRIS payment, or mark it not found | You lack the QRIS verification permission. |
| Discount | The percent is above your role's limit. |
| Reprint a receipt | The reprint is past the number of free reprints set on the server. Earlier reprints need no approval. |
| Full refund of a paid order | Always. |

For **discount**, **reprint** and **refund**, holding the approval permission yourself does not let you skip the dialog. Someone else must approve, so nobody approves their own discount, reprint or refund. For the other actions, a user who holds the permission acts without any dialog.

## What each permission is called

The permissions are set per role on [Roles](/settings/roles) under **Action permissions**. The English meanings, with the key the server uses:

| Meaning | Key |
| --- | --- |
| Void a line already sent to the kitchen | `order.void` |
| Cancel a whole open tab | `order.cancel` |
| Approve cash out above the limit | `cash.out.approve` |
| Approve a shift cash difference above tolerance | `shift.variance.approve` |
| Mark an item sold out without approval | `menu.availability.set` |
| Verify or mark not found a QRIS payment | `payment.qris.verify` |
| Approve a discount above the role's limit | `order.discount.approve` |
| Approve a receipt reprint | `order.reprint.approve` |
| Refund a fully paid order | `order.refund` |

By default, Owner and Admin hold all of them. The built-in Inventory role holds only the sold-out permission among these. Other roles hold none until a role is edited. Owner and admin cannot sign in on the tablet, but they can be the approver, so an owner with a PIN can approve a cashier's void. See [Roles and permissions](/concepts/roles-and-permissions).

## Rules and limits

- The approver must be a different person from the requester.
- The approver's PIN uses the same lock as sign-in: five wrong PINs lock it for 5 minutes. Wrong PINs also count against that person's own tablet sign-in.
- An approval lasts 120 seconds and can be used once.
- An approval is tied to the exact action. If you change the amount, line or reason after approval, it is refused and you ask again.
- The PIN is cleared from the screen as soon as **Setujui** is pressed and is not stored.

## What the cashier sees

The cashier sees the dialog open, hands over the tablet, and gets the normal result. If nobody is eligible, the dialog reads "Tidak ada penyetuju yang memenuhi syarat untuk aksi ini." Ask an admin to give someone the permission and a PIN.

## Troubleshooting

| Message | Cause | Fix |
| --- | --- | --- |
| "Tidak ada penyetuju yang memenuhi syarat untuk aksi ini." | No one else at this outlet holds the permission and has a PIN. | Grant the permission on [Roles](/settings/roles) and set a PIN on [Users](/settings/users). |
| "PIN salah. Sisa \{n\} percobaan." | Wrong approver PIN. | Re-enter. |
| "PIN penyetuju terkunci sementara karena salah berulang kali. Coba lagi nanti." | Five wrong PINs. | Wait 5 minutes or choose another approver. |
| "Penyetuju ini tidak berwenang menyetujui aksi ini." | The approver lacks the permission or is not in this outlet. | Choose another approver. |
| "Penyetuju tidak boleh orang yang sama dengan peminta." | Requester and approver are the same person. | Another person must approve. |
| "Persetujuan sudah kedaluwarsa. Minta persetujuan ulang." | More than 120 seconds passed, or it was used. | Repeat the action. |
| "Data aksi berubah sejak disetujui. Minta persetujuan ulang." | The action no longer matches what was approved. | Repeat the action unchanged. |
| Error card with **Coba lagi** | The approver list could not load. | Check the connection and retry. |
